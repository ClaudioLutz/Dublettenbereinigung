# Story 5.2: Address-Aware Stage-2 Fuzzy Prefilter

## Background

The current Stage-2 fuzzy prefilter rejects candidate pairs based solely on name similarity before considering address evidence. This creates a failure mode: **"strong address match but noisy names"** are rejected too early.

**Current Limitation:**
```
Person A: "Meyer, Hans" at "Bahnhofstrasse 10, 8001 Zürich"
Person B: "Mayer, Hanss" at "Bahnhofstrasse 10, 8001 Zürich"  (typos in name)

→ Pass business rules (identical birth date)
→ Name similarity: 65% (below 70% threshold)
→ REJECTED at Stage-2 before address is computed
→ Address ratio would be 100% (perfect match)
→ Duplicate missed despite strong address evidence
```

This is particularly problematic for fraud detection, where individuals may deliberately use name variations while maintaining the same address.

---

## Analysis Summary

### Current Stage-2 Flow (in `process_block_worker`)

**Execution Order:**
```python
# 1. Business Rules Check
if not passes_business_rules(record_a, record_b):
    continue  # Skip to next pair

# 2. Name Similarity (PRIMARY GATE)
best_score = max(normal_name_score, swapped_name_score)
if best_score < fuzzy_threshold:  # Default: 0.70
    # Phonetic borderline fallback (0.60-0.70)
    if has_phonetic_match and 0.60 <= best_score < fuzzy_threshold:
        # Allow through with phonetic assistance
        pass
    else:
        continue  # ← PROBLEM: Rejected before address computed

# 3. Address Similarity (ONLY if name passed)
address_ratio = compute_address_similarity(record_a, record_b)

# 4. Confidence Calculation
confidence = calculate_confidence(best_score, address_ratio, ...)
```

**Key Issue:** Step 2 rejects pairs before Step 3 can provide evidence.

### Real-World Impact

From production data patterns, we estimate **3-8% of true duplicates** have:
- Borderline name similarity (60-70%) due to typos, nicknames, or deliberate variations
- Strong address match (>75%) indicating same location

These are currently rejected at Stage-2 despite having strong overall evidence.

## Design Decisions

### Decision 1: When to Compute Address Evidence Early

**Option A: Always Compute Address Before Name Check (Rejected)**
- Pros: Maximum recall
- Cons: Compute address for all pairs including obvious non-matches (+40% overhead)
- Decision: ❌ Too expensive

**Option B: Compute Address Only for Borderline Name Scores (Chosen)**
- Pros: Targeted computation, controlled overhead
- Cons: Slight complexity increase
- Decision: ✅ Best balance

**Policy:**
```python
# If name similarity is borderline (60-70%), check address before rejecting
if 0.60 <= best_score < fuzzy_threshold:
    address_ratio = compute_address_similarity(record_a, record_b)
    
    # Allow through if address is strong
    if address_ratio >= 0.75:
        # Proceed to confidence calculation with "address_assisted" match type
        pass
    else:
        # Both name and address are weak → reject
        continue
```

### Decision 2: Address-Assisted Match Types

**Problem:** With current confidence formula, a `best_score=0.60` pair can never reach `confidence_threshold=70`:
```python
# Current formula
base = best_score * 50  # = 0.60 * 50 = 30
address_bonus = address_ratio * 30  # <= 30 (max)
total = base + address_bonus  # <= 60 (always below 70)
```

**Solution:** Introduce separate match types for address-assisted matches with adjusted confidence:

```python
# New match types
if match_type == 'address_assisted_normal':
    confidence = 70 + address_ratio * 10
    # Range: 70-80 (requires address_ratio >= 0.75)
    # Example: address_ratio=0.80 → confidence=78

elif match_type == 'address_assisted_swapped':
    confidence = 68 + address_ratio * 10
    # Range: 68-78 (small penalty for swapped names)
    # Example: address_ratio=0.80 → confidence=76
```

This keeps the recall gain while demanding strong address agreement.

### Decision 3: Normalize Address Comparisons

**Problem:** Current `address_ratio` compares raw `.strip().lower()` strings:
```python
# Current implementation (oversimplified)
address_a = f"{strasse_a} {plz_a}".strip().lower()
address_b = f"{strasse_b} {plz_b}".strip().lower()
address_ratio = fuzz.ratio(address_a, address_b) / 100.0
```

This undercounts matches when street spellings differ:
- `"Bahnhofstrasse"` vs `"Bahnhofstr."` → 85% match (should be 100%)
- `"Hauptstraße"` vs `"Hauptstrasse"` → 95% match (should be 100%)

**Solution:** Compute address ratio on **normalized** components:

```python
def compute_normalized_address_ratio(record_a, record_b):
    """Compute address ratio using normalized components"""
    
    # Normalize streets once per record (not per pair)
    street_a_norm = normalize_street(record_a['Strasse'])
    street_b_norm = normalize_street(record_b['Strasse'])
    
    # Normalize PLZ (already numeric, just ensure consistency)
    plz_a = str(record_a['Plz']).strip()
    plz_b = str(record_b['Plz']).strip()
    
    # Compare normalized components
    if street_a_norm and street_b_norm:
        street_ratio = fuzz.ratio(street_a_norm, street_b_norm) / 100.0
    else:
        street_ratio = 0.0
    
    if plz_a and plz_b:
        plz_ratio = 1.0 if plz_a == plz_b else 0.0
    else:
        plz_ratio = 0.0
    
    # Weighted combination (PLZ is more discriminative)
    address_ratio = 0.6 * plz_ratio + 0.4 * street_ratio
    
    return address_ratio
```

**Performance Optimization:** Precompute normalized address fields once per block (not per pair).

### Step 2: Implement Normalized Address Ratio Computation

```python
def compute_normalized_address_ratio_fast(record_a, record_b):
    """Fast normalized address ratio computation using precomputed fields"""
    
    # Use precomputed normalized fields
    street_a = record_a.get('street_normalized', '')
    street_b = record_b.get('street_normalized', '')
    plz_a = record_a.get('plz_normalized', '')
    plz_b = record_b.get('plz_normalized', '')
    
    # PLZ comparison (exact match)
    plz_ratio = 1.0 if plz_a and plz_b and plz_a == plz_b else 0.0
    
    # Street comparison (fuzzy match)
    if street_a and street_b:
        street_ratio = fuzz.ratio(street_a, street_b) / 100.0
    else:
        street_ratio = 0.0
    
    # Weighted combination (PLZ is more discriminative)
    # Require at least one component to be present
    if plz_a or street_a:
        address_ratio = 0.6 * plz_ratio + 0.4 * street_ratio
    else:
        address_ratio = 0.0
    
    return address_ratio

def normalize_street(street):
    """Normalize street name for comparison"""
    if pd.isna(street) or not str(street).strip():
        return ''
    
    street = str(street).strip().lower()
    
    # Apply normalization rules (reuse from VectorizedAddressNormalizer)
    # 1. Replace special characters
    street = street.replace('ß', 'ss')
    street = street.replace('ä', 'ae')
    street = street.replace('ö', 'oe')
    street = street.replace('ü', 'ue')
    
    # 2. Remove punctuation
    street = street.replace('.', '').replace(',', '').replace('-', ' ')
    
    # 3. Normalize common abbreviations
    abbreviations = {
        'str': 'strasse',
        'strasse': 'strasse',
        'weg': 'weg',
        'platz': 'platz',
        'allee': 'allee',
        'gasse': 'gasse'
    }
    
    for abbr, full in abbreviations.items():
        if street.endswith(abbr):
            street = street[:-len(abbr)] + full
    
    # 4. Remove extra whitespace
    street = ' '.join(street.split())
    
    return street
```

### Step 3: Implement Address-Assisted Match Types

```python
def determine_address_assisted_match_type(is_swapped, has_phonetic):
    """Determine match type for address-assisted matches"""
    if is_swapped:
        return 'address_assisted_swapped'
    else:
        return 'address_assisted_normal'

def calculate_address_assisted_confidence(match_type, address_ratio):
    """Calculate confidence for address-assisted matches"""
    
    if match_type == 'address_assisted_normal':
        # Base confidence 70, bonus up to 10
        confidence = 70 + address_ratio * 10
        # Range: 70-80 (with address_ratio >= 0.75, range is 77.5-80)
    
    elif match_type == 'address_assisted_swapped':
        # Small penalty for swapped names
        confidence = 68 + address_ratio * 10
        # Range: 68-78 (with address_ratio >= 0.75, range is 75.5-78)
    
    else:
        # Fallback (shouldn't happen)
        confidence = 70
    
    return round(confidence, 2)
```
