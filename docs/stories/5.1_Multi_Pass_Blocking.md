# Story 5.1: Multi-Pass Blocking with Phonetic+Year Pass B

## Background

The current blocking strategy uses a single pass based on address components (PLZ + Street). While this is fast and effective for most cases, it fundamentally cannot generate candidate pairs for "moved" scenarios where the same person appears at different addresses.

**Current Limitation:**
```
Person A: Hans Müller, Bahnhofstrasse 10, 8001 Zürich, Birthday: 1980-01-01
Person B: Hans Müller, Seestrasse 5, 6000 Luzern, Birthday: 1980-01-01

→ Pass A generates different blocking keys:
  - A: plz_8001_bahnhofstrasse
  - B: plz_6000_seestrasse
→ Never compared (different blocks)
→ Duplicate missed despite identical names and birth date
```

This limitation is significant for fraud detection, where individuals deliberately change addresses to evade detection.

---

## Analysis Summary

### Current Blocking Strategy (Pass A only)

**From `PhoneticBlockingStrategy.create_blocking_keys_vectorized()`:**

1. **Primary Keys** (when both PLZ and street available):
   - `plz_{plz}_{normalized_street}`

2. **Fallback Keys** (when one component missing):
   - `plz_only_{plz}_{first_letter_name}_{first_letter_vorname}`
   - `street_only_{normalized_street}_{first_letter_name}_{first_letter_vorname}`

3. **No Address Keys** (when both missing):
   - `phon_{vorname_phon}_{name_phon}` (already implemented in Story 4.1)

**Key Insight:** Records with different PLZ/street combinations are in separate blocks and never compared.

### Proposed Solution: Add Pass B for Targeted Scenarios

**Pass B Blocking Key:**
- `passB_{min(v_phon,n_phon)}_{max(v_phon,n_phon)}_{effective_year}`
- Uses min/max ordering to handle name swaps automatically
- Year component keeps blocks bounded (crucial for performance)

**Selective Generation (Key to Performance):**

Only generate Pass-B keys for records where Pass-A is weak:
1. Standard key starts with `plz_only_` or `street_only_` or `phon_` (incomplete/no address)
2. AND effective birth year is present

This keeps Pass B focused on hard-to-match cases while maintaining performance.

---

## Design Decisions

### Decision 1: When to Generate Pass-B Keys

**Option A: All Records (Rejected)**
- Pros: Maximum recall
- Cons: Doubles comparison count, +40-60% runtime
- Decision: ❌ Too expensive

**Option B: Selective - Incomplete Address Records (Chosen)**
- Pros: Targeted at problem cases, controlled overhead
- Cons: Still misses some "moved" cases
- Decision: ✅ Best balance of recall/performance

**Criteria for Pass-B Key Generation:**
```python
# Generate Pass-B key if:
1. standard_key.startswith('plz_only_') OR
   standard_key.startswith('street_only_') OR
   standard_key.startswith('phon_')
2. AND effective_year is not None
```

### Decision 2: Sub-blocking Strategy for Large Blocks

**Problem:** Pass-B blocks can be large (many people with same phonetic name + year)

**Current Approach (Problematic):**
- Chunks blocks by row order: `{key}_chunk_{i}`
- **Silent recall loss:** Duplicates in different chunks are never compared

**New Approach (Deterministic Sub-blocking):**
- Sub-block by additional stable discriminators
- For `street_only_` blocks: sub-block by effective_year first
- For Pass-B blocks: already includes year, sub-block by first_letter if needed
- Never chunk by arbitrary row order

**Implementation:**
```python

**Problem:** Once a record appears in multiple blocks (Pass A + Pass B), the same pair can be found twice.

def _deduplicate_pairs(self, matches_df):
    """Remove duplicate pairs, keeping higher confidence match"""
    # Sort by confidence (descending)
    matches_df = matches_df.sort_values('confidence', ascending=False)
    
    # Create pair identifier (sorted to handle A-B vs B-A)
    matches_df['pair_id'] = matches_df.apply(
        lambda row: tuple(sorted([row['Crefo_A'], row['Crefo_B']])),
        axis=1
    )
    
    # Keep first occurrence (highest confidence)
    deduplicated = matches_df.drop_duplicates(subset=['pair_id'], keep='first')
    
    # Drop temporary column
    deduplicated = deduplicated.drop(columns=['pair_id'])
    
    return deduplicated
```

## Solution Design

### Step 1: Extend `PhoneticBlockingStrategy` to `MultiPassBlockingStrategy`

Create new class that adds Pass-B key generation:

```python
class MultiPassBlockingStrategy(PhoneticBlockingStrategy):
    """Multi-pass blocking: Pass A (address) + Pass B (phonetic+year) for targeted records"""
    
    def __init__(self, max_block_size: int = 1000):
        super().__init__(max_block_size)
        self.pass_b_generated = 0  # Track statistics
    
    def create_blocking_keys_vectorized(self, df: pd.DataFrame) -> pd.DataFrame:
        """Create blocking keys with selective Pass-B generation"""
        
        # Get Pass-A keys from parent class (includes phonetic for no_address)
        pass_a_keys = super().create_blocking_keys_vectorized(df)
        
        # Ensure phonetic codes are computed (parent may have done this)
        if 'vorname_phon' not in df.columns:
            from cologne_phonetics import encode
            df['vorname_phon'] = df['Vorname'].apply(
                lambda x: encode(str(x)) if pd.notna(x) and str(x).strip() else ''
            )
            df['name_phon'] = df['Name'].apply(
                lambda x: encode(str(x)) if pd.notna(x) and str(x).strip() else ''
            )
        
        # Compute effective birth year (prefer Geburtstag, fallback to Jahrgang)
        df['effective_year'] = df.apply(
            lambda row: self._extract_year(row['Geburtstag']) 
                        if pd.notna(row.get('Geburtstag')) 
                        else row.get('Jahrgang'),
            axis=1
        )
        
        # Identify records that need Pass-B keys
        needs_pass_b = (
            (pass_a_keys.str.startswith('plz_only_') |
             pass_a_keys.str.startswith('street_only_') |
             pass_a_keys.str.startswith('phon_')) &
            (df['effective_year'].notna())
        )
        
        # Create result DataFrame with Pass-A keys
        result_df = pd.DataFrame({
            'index': df.index,
            'blocking_key': pass_a_keys,
            'blocking_pass': 'A'
        })
        
        # Generate Pass-B keys for selected records
        if needs_pass_b.any():
            pass_b_records = df[needs_pass_b].copy()
            
            # Create Pass-B blocking keys
            pass_b_keys = pass_b_records.apply(
                lambda row: self._create_pass_b_key(
                    row['vorname_phon'],
                    row['name_phon'],
                    row['effective_year']
                ),
                axis=1
            )
            
            # Create Pass-B DataFrame
            pass_b_df = pd.DataFrame({
                'index': pass_b_records.index,
                'blocking_key': pass_b_keys,
                'blocking_pass': 'B'
            })
            
            # Concatenate Pass-A and Pass-B keys
            result_df = pd.concat([result_df, pass_b_df], ignore_index=True)
            
            self.pass_b_generated = len(pass_b_df)
        
        return result_df
    
    def _create_pass_b_key(self, vorname_phon, name_phon, year):
        """Create Pass-B key: passB_{min_phon}_{max_phon}_{year}"""
        # Use min/max to handle name swaps automatically
        phon_min = min(vorname_phon, name_phon) if vorname_phon and name_phon else ''
        phon_max = max(vorname_phon, name_phon) if vorname_phon and name_phon else ''
        
        return f"passB_{phon_min}_{phon_max}_{int(year)}"
    
    def _extract_year(self, date_str):
        """Extract year from date string"""
        try:
            if isinstance(date_str, str):
                return int(date_str.split('-')[0])
            elif hasattr(date_str, 'year'):
                return date_str.year
        except:
            pass
        return None
```
